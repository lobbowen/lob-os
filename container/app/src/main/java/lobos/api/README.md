# api —— 调用面

系统对外的那一面。只有这里的东西能被程序看到。

程序（控制面板也是程序）经由这一面进系统，不直接碰内核或服务。

## 两种接入

| 方式 | 谁用 | 载体 |
|---|---|---|
`api/bridge/` | 进程内的快应用（经 extModule） | `CapabilityBroker.invokeLocal` |
`api/ipc/` | 独立的本地程序进程 | `CapabilityBroker` 的 unix socket + JSON-RPC |

两者共用同一套方法表与鉴权规则 —— 区别只在传输。

## 职责

- **鉴权**：握手校验会话令牌与能力组
- **编解码**：帧格式、参数校验、错误码
- **转发**：把方法转给 `services/` 的实现
- **留痕**：每次调用一行审计

这一层**无状态**。它不持有业务数据，只做转发与记录。

## 依赖方向

```
api/  →  services/  →  kernel/
```

**只能向下。** 这是最外一层，不被任何层依赖。
