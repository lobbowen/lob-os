# services —— 服务层

有状态、有生命周期、常驻的地方。

内核提供机制与形状，这一层做**决策**：装不装、跑不跑、能不能用、用哪个。

## 职责域

| 目录 | 职责 |
|---|---|
`supply/` | 供给：铺件、记账、更新、目录、远端清单、下载器 |
`reg/` | 注册表：有哪些 unit、什么版本、什么运行态 |
`supervise/` | 监管：起停、探活、退避、隔离、开机对账 |
`perm/` | 权限：定义、实测、记账、取权路径 |
`app/` | 应用框架：快应用前后端、运行时适配、桌面图标 |
`host/` | 宿主：前台服务、开机拉起、常驻状态 |
`log/` | 日志与诊断：事件、死因归因、日志包 |

## 「件」在这一层，不在内核

`bash` `rg` `jq` `dimina` `node` 都是**用户态程序**，住在 `usr/lib/<id>/<版本>/`。

内核不承认「件」这个概念——它只保证落在约定形状里的东西**找得到、跑得起、依赖解得开**。

铺件、记账、更新是这一层的事。

## 「运行时」也是这一层的事

`dimina` 与 `node` 同类：跑程序要用的引擎。

服务层提供 `RuntimeRegistry`（「给我一个能跑 JS 的运行时」），
编译期不绑定具体实现。dimina 缺失时能降级，而不是崩。

## 依赖方向

```
services/  →  kernel/
```

**只能向下。** 不 import `api/`。
