# 三项判断

基于 `docs/BASE-ENV-INVENTORY.md` 的待判三项，逐项给判断。
判据全部来自代码实查，不凭印象。

---

## 一、时区数据 `zoneinfo` —— **进**

### 判据

| 查什么 | 结果 |
|---|---|
| 代码怎么用时间 | 全部是**毫秒时间戳 + `SimpleDateFormat` 本地格式化** |
| 有没有用到时区 | `zoneinfo` / `TZ=` / `TimeZone` / `DateTimeZone` **零命中** |
| Android 有什么 | 系统内部有时区，但程序读不到（我们没有 `/usr/share/zoneinfo`） |

### 为什么还是该进

代码自己不用 ≠ 程序不用。**底座是给程序用的，不是给我们自己用的。**

程序一旦调这些就会踩空：

```js
new Date().toString()                    // → "Wed Oct 08 2026 14:34:25 GMT+0800"
Intl.DateTimeFormat().resolvedOptions()   // → 时区名
Calendar.getTimeZone().getID()            // → "Asia/Shanghai"
```

Node 尤其敏感——它启动时就要初始化时区与 locale，缺了会退化成 UTC 或直接警告。

### 结论

**进。** 底座没有时区，程序算本地时间就是错的（用户看到的时间和用户所在地差 8 小时）。
Linux 有 `/usr/share/zoneinfo`，我们也得有。

**裁剪**：全量 tzdata 约 400KB–1MB，可以只留常用时区（中国 `Asia/Shanghai`、
UTC、主要洲际），其余按需。**这一条与"不受体积约束"不冲突**——不是不能大，是不必无谓地大。

## 二、locale 定义文件 —— **进**

### 判据

| 查什么 | 结果 |
|---|---|
| 我们设了什么 | `LANG=C.UTF-8` |
| 有没有定义文件 | 零提及 |
| Android 有什么 | `/system/etc/locale`（各厂商内容不同，**我们不保证有**） |

### 为什么该进

`LANG` 只是**声明**"我要什么语言环境"，实际定义由 locale 源提供。
定义缺失时的后果不是报错，是**静默降级**：

- `setlocale(LC_ALL, "")` 返回 NULL，程序以为设置成功
- 数字/日期/排序按 C 规则走（字节序，不是本地序）
- node 在 POSIX locale 下会打 ICU 警告然后回退

**静默降级比报错更难查**——程序跑起来了，只是结果不对。

### 结论

**进。** 而且这条比时区更该进：locale 缺失是**静默错误**，时区缺失至少有明显症状。

**形态**：不用全量 locale 源。一份 `C.UTF-8` 的定义 + 常用（`en_US` / `zh_CN`），
足够覆盖 node 与绝大多数程序。几十 KB。

## 三、`/etc/services` —— **不进**

### 判据

| 查什么 | 结果 |
|---|---|
| 代码里有没有消费者 | `getservbyname` / `getprotobyname` / `services` **零命中** |
| 唯一命中 | `PermissionCatalog.kt` 的 `enabled_accessibility_services` —— **子串误报** |

### 为什么这次不一样

前两项有**真实风险**（时区算错、locale 静默降级）；这一项：

- 我们自己的代码零使用
- 程序侧只有 `getservbyname(443)` 这种查法才会用到
- 而 `curl https://…`、`git clone https://…` 走的是**协议里的 scheme**，
  不查 `/etc/services`

### 结论

**不进。**

判据（与前两项不同）：不是"有没有风险"，而是**"有没有真实消费者"**。
`zoneinfo` / `locale` 是**几乎每个程序都会碰**的基础设施；
`/etc/services` 只有显式查端口名映射的程序才碰，属于小众。

如果将来发现程序确实需要（比如某个库硬依赖 `getservbyname`），
再补也不迟——**20KB，秒加**。

## 四、汇总

| 项 | 判断 | 依据 | 成本 |
|---|---|---|---|
| 时区 `zoneinfo` | **进** | 程序调 `new Date().toString()` / `Intl.*` 就会踩空；代码自己不用不代表程序不用 | 400KB–1MB（可裁剪） |
| locale 定义 | **进** | 缺失是**静默降级**，比报错更难查；node 启动即依赖 | 几十 KB |
| `/etc/services` | **不进** | 零消费者；`https` 走协议不查这个表 | 20KB（将来可加） |

## 五、两条不同的判据

这三项我用了**两把尺子**，值得说清：

| 判据 | 适用 | 项 |
|---|---|---|
| **「几乎每个程序都会碰」** | 基础设施，缺了会静默出错 | 时区、locale |
| **「有真实消费者才补」** | 小众能力，缺了只影响特定程序 | `/etc/services` |

**不该拿同一把尺子量所有东西**——那会导致底座无限膨胀；
也不该为省体积砍掉几乎所有程序都要的东西——那会导致底座不可靠。

## 六、顺带确认一件事

这三项之外，**终端（PTY + termios）** 是零实现，不在这三项里——
它不是"件"而是"能力"，且是 Linux 有而我们完全没有的。

它比这三项都重要：**`busybox` 能装上，但没有 PTY 就只是一堆命令，不构成可用的环境。**
