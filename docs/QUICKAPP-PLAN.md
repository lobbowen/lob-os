## 1. 三件必须先想清楚的事

### 1.1 一个快应用 = 前后端一个包，运行时是两个进程

标准里前端是单体包，**没有后端概念** —— 这是我们唯一必须自己发明的地方。

已定的部分：

- 后端端口**装时分配、写死注册表**（段 `80000-89999`，按安装顺序取第一个空闲）
- 前端从 `config.json` 读端口（**已证可行**：`RemoteUpdateManager.kt:162` 表明 dimina
  自己在装时改写 config.json 并加 `hostManaged` 标记，说明宿主塞自定义字段被支持）
- 兜底走 `extBridge`（我们已注册 `lobos` 模块，加个 `backendEndpoint` 事件即可）

**明确不用标准的 mDNS**（`LocalNetworkApi`）：它解决跨设备发现，我们在同机；
它要求后端实现 mDNS 广播，而 Android 后台被杀即断（这台 OPPO 上 `o-kill` / HANS 冻结在刷）。

### 1.2 前端包与后端包怎么合成「一个包」

标准前端包 = `config.json` + `main/`（app-config / logic / ux…）；
我们后端 = `program-manifest.json` + 入口程序。**两者结构完全不同。**

**待定**（见 §4）：是一个 zip 装两套 / 发布两个包由安装器配对 / 安装器合成。

### 1.3 前端包怎么产出

编译器在 `fe/packages/compiler`（pnpm workspace，独立于安卓模块）。

**待定**（见 §4）：vendoring 源码 / 从 npm 装 / **不由我们编**（发布方自己编好，我们只验结构）。

## 2. 开发阶段

### 阶段 A：先证明「一个快应用能跑起来」（当前）

**目标**：装一个带前端的快应用 → 桌面有图标 → 点开有自己的界面。
**不含**：后端联动、能力桥、注册表。

| 步 | 做什么 | 验什么 |
|---|---|---|
| A1 | 定前端包形态（§1.2） | 形态定了、门禁能守 |
| A2 | 打通前端包产出（§1.3） | 跑通一个 demo，产出合法的三个必需文件 |
| A3 | `QuickAppHost.install` 喂真包 | 装得上（`isExistsApp` 为真） |
| A4 | 桌面图标 | 装完出图标、点开是它自己的窗口 |

**A2 是这一阶段最大的未知**——编译器能不能在 CI 或本地跑起来。

### 阶段 B：后端联动（一次安装 = 一套完整程序）

| 步 | 做什么 |
|---|---|
| B1 | 程序注册表（id ↔ 端口 ↔ 前后端路径） |
| B2 | 端口装时分配（`80000-89999`） |
| B3 | 端口注入前端（写 `config.json` 的 `hostManaged` 字段） |
| B4 | 后端环境变量注入 `PORT` |
| B5 | 前后端一起装、一起升、一起卸 |

### 阶段 C：能力边界

| 步 | 做什么 |
|---|---|
| C1 | `LobosBridge` 接上 `CapabilityBroker`（现是 ping 占位） |
| C2 | 前端不碰系统能力、后端调能力的链路打通 |
| C3 | 远端后端（`backend.remote`）支持 + SSRF 防护 |

### 阶段 D：控制面板

控制面板是第一个系统快应用，走 B/C 已建立的链路。**页面设计最后做。**

### 阶段 E：规范（给开发者）

到这一步形态全定了才写得出来。含：哪些能力不可用、后端端口规矩、前端取地址规矩、
远端后端怎么写、跨域怎么处理。

## 3. 顺序依赖

```
A1 前端包形态 ──┐
A2 前端包产出 ──┼─→ A3 装得上 ─→ A4 桌面图标 ────── 阶段 A
               │
B1 注册表 ──────┼─→ B2 端口分配 ─→ B3/B4 注入 ─→ 阶段 B
               │
C1 能力桥 ──────┴─→ 阶段 C ─→ 阶段 D（控制面板）─→ 阶段 E（规范）
```

**A1 与 A2 卡住阶段 A 的全部**，是当前最该定的两件事。

## 4. 当前待决（只有这两个）

### 待决一：前端包与后端包怎么合成「一个包」

- **甲**：发布物是一个 zip，里面 `frontend/` + `backend/` 两套，安装器各落其位
- **乙**：发布两个包（`.frontend.zip` + `.backend.zip`），安装器配对
- **丙**：前端由 dimina 编译产出、后端由我们产出，**在安装器里合成**

### 待决二：前端包怎么进我们的流程

- **甲**：vendoring `fe/packages/compiler` 源码
- **乙**：从 npm 装编译器
- **丙**：**不在我们这编** —— 发布方自己编好，我们只验结构

丙最省事（我们不是工具链供应商）；甲最可控。

**这两个定了我就开始 A。**
