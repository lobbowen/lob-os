# PACKAGE-BUILD · 安装包生产构建规范（可执行版）

- 作者：core-architect（04）
- 日期：2026-10-19
- 状态：**可执行版**。配套的原则版与判据在 `docs/spec/INSTALL-AND-REGISTRY.md`。
- 边界：本文件只写字。**05 今天在改实现，本规范不指定任何实现改法。**

---

## 〇、三条原则（用户今天定的，本规范是它们的可执行版本）

```
一 构建时就知道哪些是库、哪些是程序
二 库装到库目录、程序装到程序目录
三 注册表记「库在哪里」与「程序在哪里」；运行期只读，不判断
```

**判别形式（本规范存在的理由）**：**一个人照着它做，能不能不做任何判断就把一个包建出来？**

**=> 本文件每一步都是「命令 + 读数 + 判读」，而每一步的判读只允许三种结果：继续、判红、人工介入。**

**=> 而其中每一项能不能核，答案在同一张表里：每一项后面都写了用什么命令、能看出什么。**

## 一、构建一个包的完整步骤（照着做，不需判断）

### 步骤 1 · 把产物按目录摆好

**做什么**：库那一份放库目录，程序那一份放程序目录。**别的什么都不做。**

| 项 | 怎么核 |
|---|---|
| 命令 | `find <产物目录> -type f \( -path '*/lib/*' -o -path '*/bin/*' \)` |
| 读数 | 每一个字节落在且只落在一个目录下 |
| 判读 | 有字节同时落两处 ⇒ 判红（步骤 3 会拦） |

### 步骤 2 · 由构建跑一次形态判定

**做什么**：**不做任何人工判断** —— 跑那一步，它自己读每一份字节的 ELF 头得出形态。

**形态表（本规范照录其四值，不新增）**：

| 形态值 | 它意味着 |
|---|---|
| `exec` | **可执行文件那一类** |
| `dyn-interp` | **动态链接类且带解释器段** |
| `dyn-plain` | **动态链接类且无解释器段** |
| `unreadable` | **读不出** |

**「它是程序」的判定 = 前两种值。（本规范实读确认该判定是单点的：它就是「值等于那两个之一」。）**

| 项 | 怎么核 |
|---|---|
| 命令 | 对每一份字节各跑一次那个形态判定 |
| 读数 | 每份字节得一个上面四值之一 |
| 判读 | 得 `unreadable` ⇒ **判红，不猜**（缺字段报缺，不拿缺省当值） |

### 步骤 3 · 按下表判红或取入口（这是唯一一处分支）

**照抄这张表，不要改判定次序**：

| 条件 | 动作 |
|---|---|
| 程序目录下**恰好一个**「程序形态字节」 | **入口取程序那一份**，并记下它是否同时带库 |
| 程序目录下**多于一个**程序形态字节 | **判红**（这一件有多个入口，请拆成别的件） |
| 程序目录下**有文件但没一个是程序形态** | **判红**（那些不是入口） |
| 程序目录下**零个程序形态字节**、库目录下**恰好一个**主名 | **入口取库那一份**，记「非混合」 |
| 库目录下**多于一个**主名 | **判红**（纯库件的落位结果不唯一） |
| 两者都没有 | **判红**（没有落位结果，不写没有依据的入口） |
| 入口形状不对（不是那两种形状之一，或含上跳） | **判红** |
| 入口指向的文件在落位结果里不存在 | **判红** |

**而「判红」的实际动作（照录，不是口头）**：**报错并以非零退出。**

| 项 | 怎么核 |
|---|---|
| 命令 | 跑步骤 2 那一步，看它的退出码 |
| 读数 | 非零 ⇒ 已判红；**且报错信息里必须带件名与判红原因** |
| 判读 | **它以非零退出 ⇒ 整条链上构建那一道已生效**（本规范 §五十 那一条保证就在这一跳） |

### 步骤 4 · 生成产物自描述

**做什么**：把步骤 3 的结果写进那份产物自描述。

**必须写的**（本规范只列，不指定格式）：

| 字段 | 它是什么 |
|---|---|
| 件名与版本 | **从钉值表来，不手写** |
| 架构 | **从构建配置来** |
| 入口 | **步骤 3 的结果** |
| 内容摘要 | **从打包结果算** |
| **库的名字列表** | **步骤 1 扫出来的那些库主名** |
| **它是不是混合** | **步骤 3 的结果** |

**而今天那三个字段（库列表、混合标记、库名列表）已算出而无人读** —— **本规范在此记下这一格的状态，见 §三。**

| 项 | 怎么核 |
|---|---|
| 命令 | 读那份产物自描述 |
| 读数 | 六个字段都在，且入口那一个与步骤 3 的输出一致 |
| 判读 | 任一缺失 ⇒ 判红 |

### 步骤 5 · 打包

**做什么**：**存链接本身**（那个选项的作用是「把链接原样存进包，而不是展开它」）。

| 项 | 怎么核 |
|---|---|
| 命令 | 列出包里条目 |
| 读数 | **每一份链接在包里仍是链接** |
| 判读 | **链接被展开成普通文件 ⇒ 判红**（这就是本规范 §五十五 那一族在打包侧的表现） |

### 步骤 6 · 移进产物目录

**做什么**：打包到工作目录，**之后**才移进产物目录。

**而本步存在的原因（本规范写明，因为它是今天查到的）**：**「产物在构建那一刻」与「产物在产物目录里」是两个时刻，而本规范要求前者被保住。**

| 项 | 怎么核 |
|---|---|
| 命令 | 看最终包名的构成：件名 + 版本 + 内容摘要 + 架构 |
| 读数 | 四段齐全，且件名段是这一件的件名 |
| 判读 | **件名段对不上 ⇒ 那不是这一件的包**（见 §四） |

### 步骤 7 · 运行期只读

**做什么**：运行期**读那两份自描述**，据此知道库在哪、程序在哪。

**而运行期明确不许做的（原则三的另一半）**：

| 运行期不许做 | 它归哪一族 |
|---|---|
| **读字节头判「这是不是程序」** | 形态由构建期判定（§五 禁那一类） |
| **按目录名判「这是库还是程序」** | 同上 |
| **挑「哪一份才是入口」** | 入口是步骤 3 的结果，运行期只读 |
| **自己算一份缓存/表** | 那是另一族（§三十八） |

| 项 | 怎么核 |
|---|---|
| 命令 | 搜运行期代码里读字节头判形态的地方 |
| 读数 | **零命中，且阳性对照成立**（同一模式串在构建侧命中） |
| 判读 | 有命中 ⇒ 违反原则三 |

## 二、混合件那一条（照 man 原文）

**原文依据（用户今天提供）：**

> 「只有单一的那一份可执行文件，但那份文件表现得像大量小工具。」

**而按那一份原文，那一类件**只有程序这一个角色**，而它响应多个名字。

**⇒ 本规范据此写死三条（这一族唯一的三条）：**

| # | 条 | 判别 |
|---|---|---|
| 1 | **那一份字节只放在程序目录** | **库目录下不应有它那一份** |
| 2 | **多个名字不是多份字节** | **名字对应磁盘上一份独立的字节吗？不独立 ⇒ 它是派生名，一次复制都不必做** |
| 3 | **那些名字由那份字节自己给出** | **它响应哪些名字，是那份字节的属性；构建期读到它，且只许写算出来的** |

**而第 3 条的判别（本规范 §52.4 那一条）：**

> **那个名字列表是从字节自身读出来的，还是人写下来的？**
> **算出来的 ⇒ 可写进产物。人写的 ⇒ 按自我描述那条不进包。**

**而这一族今天为什么必须写成三条（01 的观察，本规范照录）**：

| | 问题 | 形态 |
|---|---|---|
| **其一** | 程序目录下多份相同字节 | **一份字节被复制成多份** |
| **其二** | 库目录下一份无人消费的字节 | **一份不存在的库角色被造了出来** |

**=> 而按上面第 1 条与第 2 条，两个方向同时消掉**：它只有程序这一个角色，而它的多个名字是派生物。**

**而判读要分清「判红」与「不是缺陷」**：**

> **一条判据对一个「它今天靠另一条路才跑通」的件判红，这不叫误报** —— **它报的是「这一件不满足这条规则」，而处置只有两条：改规则（允许多个程序形态字节）或改这一件（拆）。**

| 项 | 怎么核 |
|---|---|
| 命令 | 程序目录下逐条判形态，数出「程序形态字节」有几个 |
| 读数 | 一个数 |
| 判读 | **多于一个 ⇒ 判红**（除非按上面那条判别，认定它本来就有多个入口而改规则） |

## 三、可被机器核（判别：一个包建出来之后，只读它的产物能不能认出它是库还是程序）

**答案：能，而只有一处读数源** ——

| 只读产物要回答 | 答案在哪 | 为什么可靠 |
|---|---|---|
| **它是不是程序** | **那两份自描述里的混合标记与入口形状** | **构建期已判过，运行期只读** |
| **库在哪** | **自描述里的库名字列表** | **由步骤 1 扫出来** |
| **程序在哪** | **自描述里的入口** | **由步骤 3 决定** |

**=> 而这一条的成立有一个前提（本规范写死）**：**那三个字段今天已算出却无人读** —— **本规范 §五十 与 §五十一 已记，而它的读侧是本规范的第六节。**

### 3.1 一份包建成后的机器核步骤

| # | 核什么 | 命令 | 读数 | 判读 |
|---|---|---|---|---|
| 1 | **包内链接是否仍是链接** | 列出条目 | 链接标记仍在 | 否 ⇒ 步骤 5 失效 |
| 2 | **入口形状** | 读自描述 | 是那两种形状之一 | 否 ⇒ 步骤 4 失效 |
| 3 | **入口指向的文件存在** | 检查那个路径 | 存在 | 否 ⇒ 步骤 3 失效 |
| 4 | **库列表与实际一致** | 比对自描述里的库列表与库目录 | 逐条相等 | 不等 ⇒ 步骤 1 或 4 失效 |
| 5 | **包名三段齐全** | 看包名构成 | 件名 + 版本 + 摘要 + 架构 | 否 ⇒ 这不是一件的包（§四） |

**而第 5 条是本规范 §五十六 那一族的判红条件。**

### 3.2 而这一节的边界（本规范据实标）

| # | 边界 |
|---|---|
| 1 | **第 1 条今天未核到** —— 因为要核它需要那一件自己的包，而本机产物目录里没有（§五十七 已记） |
| 2 | **第 4 条今天不成立** —— 那两个字段有算出的地方而无读的地方，读侧是第六节 |
| 3 | 本规范核的是当前工作树，**工作树今天有他人未提交的改动** |

## 四、一份东西与这一件无关的三问（本规范 §57.2 那个三问，可执行版）

| 问 | 怎么核 | 不通过时 |
|---|---|---|
| **路径能不能区分** | 这一格在哪个目录 | **按路径归档的读数不可作证** |
| **名字对不对** | 包名里的件名段是不是这一件 | **不是 ⇒ 它与这一件无关，哪怕同目录同型** |
| **能不能被取件选中** | 取件那一步的件名白名单里有它吗、按资产名精确相等吗 | **不在 ⇒ 它不会被选中** |

## 五、为什么这一格归构建期而不是运行期（本规范写死，理由是它已在别处论证过）

**判别**：**整条链上，谁是唯一一道拦截？**

**答**：**构建期那一次判红。**

**=> 而由此得出两条约束（今天链条上的形态）：**

| # | 约束 |
|---|---|
| 1 | **运行期那两道（字段校验、文件在位）拦不住「入口被算成一份库」** —— **所以构建期那一处错了，链上没有第二道** |
| 2 | **运行期对「那一份字节是库还是程序」这一问一个字都不回答** |

---

## 六、运行期读侧尚未接上的那一格（本规范写明它是本规范的前置）

**事实**：**库名字列表与混合标记今天已算出，而运行侧零读者**（本规范实读复核：运行侧命中全在注释里）。

**=> 而按本规范 §三，它使「可被机器核」这一节第 4 条今天不成立。**

**判别形式**：**今天读一个包，能不能从产物得出「它带了哪几份库」？不能 ⇒ 那一格尚未产生读侧。**

**而本规范给它的次序（不是实现建议）：**

```
先答：落位之后那份字节的「几处各是什么角色」还认得出来吗
  认不出（只剩若干条各自独立的链接）⇒ 「几处各是什么角色」今天没有被记下来
  ⇒ 而那一格要先解决「认不认得出」，再讨论「那两格写不写进产物」
```

**=> 而本规范只把这一格写成「未接上」，不写实现。**
