# 执行规范

本规范约束本地构建与发布的执行行为。违反这些原则会造成 CDN 污染、
状态不可追溯、可用产物丢失。所有发布相关操作必须先读本规范。

---

## 一、本地构建产物的留存原则

1. 构建过程中**失败的、未验证的、中间态的产物不留存**，发现即清理。
   包括：编译失败的半成品、打包报错的 zip、试验性的 sysroot/stdlib 目录、
   被新版本取代的旧件。
2. 判断标准：只有"已验证可用"的产物才有资格留存在本地的备份目录。
   未经验证的产物留在本地，迟早会被误当作正式件使用。
3. 每个构建步骤结束后，立即清理该步骤产生的临时文件与中间目录。

---

## 二、七牛 CDN 的上传原则

1. 七牛上**只上传可用的正式发布内容**。任何未验证的、试验性的、
   临时测速的文件一律不上七牛。
2. 正式内容走正式目录（见第四节），测试内容走测试目录，两者严格隔离。
3. 上传前必须确认：该产物已通过本地验证（能执行、模块齐全、
   清单聚合正确、签名自检通过）。未过验证的不传。
4. 一次发布只上传该次 revision 涉及的正式件与清单，不夹带历史残留。

---

## 三、测试目录原则

1. 需要验证商店下载/安装流程时，用**测试目录**（testing），
   不用正式目录，也不往正式目录塞测试件。
2. 测试目录由用户手动清空，可随时清；里面的内容不视为正式产物。
3. 测试版 APK 指向测试目录，正式版 APK 指向正式目录。
   当前开发阶段全部用调试版 APK，按目标目录区分用途。
4. 不允许在测试目录里验证通过后，把测试件直接"搬"到正式目录了事——
   正式件必须由正式构建流程产出并重新验证。

---

## 四、正式目录结构

正式根：`https://lobcdn.zll.ink/official/`
```
official/
  component/<件名>-<版本>-<sha>-android-arm64.zip     正式件包
  component-canary/component-manifest.json             正式清单
  component-canary/component-manifest.json.sig
  component-canary/native-manifest.json
  component-canary/native-manifest.json.sig
```
测试根：`https://lobcdn.zll.ink/testing/`（结构相同，可清空）

旧的 `component/`、`component-canary/`（根级）、`test-piece.zip` 等历史残留
不属于本规范管理范围，由用户自行清理；新流程不再向这些路径写任何东西。

---

## 五、本地备份原则

1. 本地必须保留一份**已验证可用的备份**：正式件包、签名清单、
   签名私钥、keystore、构建脚本、凭证配置。
2. 备份目录与构建中间目录分离：备份只进不改，中间目录可随时清理。
3. 备份的作用是：七牛被清空或出错时，能从本地原样恢复正式发布，
   不需要重新构建。
4. 备份内容随代码版本演进更新，但旧备份在确认新备份验证通过前不删。

---

## 六、执行顺序（每次发布）

1. 本地构建 → 本地验证（能执行、模块齐、清单对）
2. 验证通过 → 落入本地备份目录
3. 从备份目录上传到**正式目录**（只传本次 revision）
4. 上传后回读校验
5. 设备从正式目录安装验证
6. 清理本次构建的中间产物（备份目录除外）

任何一步失败，停止，不进入下一步，不把失败产物留在备份或 CDN。
